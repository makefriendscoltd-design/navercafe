실행 전 `.venv312/bin/python content_queue_guard.py --live`가 status=pass인 경우에만 그 결과의 source_key 한 건을 처리한다. 다른 항목을 고르거나 차단을 우회하지 않는다. 지시문 정본은 Git 추적 outputs/cafe-publish-queue-20260823/automation_prompt.txt이며 실제 등록 지시문과 달라지면 발행하지 않는다.

이 자동화는 검증을 마친 네이버 카페 글을 토요일·일요일을 포함해 매일 `10:00`부터 `23:00`까지 Asia/Seoul 기준 매시간 확인하는 재시도 큐다. 주말을 건너뛰지 않는다. 카페 성공 발행은 하루 최대 2건, 성공 간 최소 5시간이며 실행 한 번에 최대 한 항목만 시도한다. 쇼츠 공개와 카페 발행은 완전히 독립이므로 카페 실패를 이유로 쇼츠 provider ID, 공개 상태, 예약 시각을 변경하거나 쇼츠 CRM 기록을 만들지 않는다. 작업 루트는 /Users/apple/orca/navercafe이고 큐 파일은 outputs/cafe-publish-queue-20260823/queue.json이다. 큐에 없는 소스나 임의 원고를 만들지 않는다. Selenium/Playwright/Chrome 쿠키를 사용하지 말고 Aside CLI u0와 공급자 잠금을 우회하지 않는다.

매 실행마다 다음 순서를 지킨다.

1. 큐 JSON을 읽고 현재 시각을 Asia/Seoul 기준으로 계산한다. 각 `source_key`는 동일 원본으로 만든 카페글·쇼츠·카드뉴스의 공통 식별자다. 카페 provider URL이 없는 source_key는 쇼츠·카드뉴스가 완료됐더라도 카페 미완료로 남겨 계속 발행 대상으로 취급한다. status=published이고 카페 provider URL까지 확인된 항목은 다시 시도하지 않는다. 각 항목의 shorts_* 필드는 읽기 전용 참고값이며 어떤 경우에도 이 자동화가 수정하지 않는다.
2. KST 오늘 실제로 공급자 게시 URL까지 확인되어 status=published가 된 카페 항목 수를 센다. `provider_uncertain_do_not_retry.json` 또는 `published_but_verification_failed_do_not_retry.json`에 cafe.naver.com 게시 URL이 남은 미조정 항목도 당일 성공 한 칸으로 임시 계산하고, 그런 항목이 하나라도 있으면 새 공급자 동작 없이 읽기 전용 공개 조정만 한 뒤 종료한다. 2건 이상이면 아무것도 발행하지 않고 종료한다. 가장 최근 카페 성공 시각으로부터 5시간이 지나지 않았으면 아무것도 발행하지 않고 종료한다. 성공 시각은 result JSON의 공급자 검증 완료 시각을 우선하고, 없으면 큐의 last_attempt_at을 쓴다.
3. do_not_retry=true 또는 status가 blocked/reconcile_required인 항목은 절대 선택하지 않는다. 그 밖에서 not_before가 현재 이하이고 attempts=0인 pending 항목 중 not_before가 가장 빠른 한 건을 고른다. 그런 항목이 없으면 status=failed이고 next_eligible_at이 현재 이하인 항목 중 next_eligible_at이 가장 빠른 한 건만 고른다. 어느 경우에도 실행 한 번에 두 건 이상 시도하지 않는다. 선택할 항목이 없으면 큐를 바꾸지 않고 종료한다.
4. 선택한 항목의 approval_gate, launch_gate, local_gate와 manifest를 먼저 검사한다. eligibility_command가 있으면 공급자 동작 전에 그 명령을 정확히 한 번 실행하고 종료코드 0과 `status=pass`, `scope=cafe_only`를 확인한다. publisher_command가 있는 신규 항목은 기존 `cafe/06_cafe_manifest.json`을 유일한 카페 정본으로 사용하고, source_key·제목·AI 자동화&수익화 정보 카테고리·소제목 인용구 5개·이미지 5개·패밀리데이 원문 URL과 OG 카드·▶ 원본 영상 문단·두 형태의 원본 YouTube URL과 미리보기 카드가 정확해야 한다. 실행 당일 Aside u0 로그인과 정확한 제목·source_key·`youtu.be`/`youtube.com/watch` URL의 공개 중복 0건을 새로 확인하지 못하면 발행하지 않는다. Cafe-only local_gate는 Cafe 정본·게시 안전 조건만 판정하며, Shorts/Community의 만료된 `selected_schedules_future` 값은 Cafe 판정에 넣지 않는다. 다만 Shorts/Community 게이트·일정·상태 파일은 그대로 보존하고 수정하지 않는다.

6. publisher_command가 없는 기존 항목에서만, 임시글 복원 경로가 정확한 제목 누락·인용구 제목 불일치·등록 완료 미확인·공급자 업로드 거절로 실패하면 같은 실행에서 아래 복구 명령을 최대 한 번 실행한다. publisher_command가 있는 항목, 로그인 실패, 공급자 잠금 실패, 공개 중복 또는 로컬 원고/이미지 검증 실패에는 복구 명령을 실행하지 않는다. 복구 스크립트는 큐 manifest의 동일 원고와 5개 이미지로 새 편집기 상태를 구성하고 모든 DOM 게이트를 다시 통과한 경우에만 발행한다.

7. 명령 종료코드와 별개로 publisher_command 항목은 provider_evidence, 기존 항목은 result JSON을 읽고 큐 상태를 갱신한다. publisher_command가 비정상 종료했더라도 do_not_retry 증거에 게시 상태와 cafe.naver.com URL이 있으면 failed 재시도 대상으로 만들지 말고 status=reconcile_required, next_eligible_at=null, do_not_retry=true로 잠근다. 이후 실행은 공개 페이지 읽기 전용 검증으로만 published 또는 not_published를 확정한다. status가 `published_verified` 또는 `published`이고 providerUrl 또는 provider.url이 실제 cafe.naver.com 게시글 URL이며 공개 페이지에서 Family Day OG 카드와 YouTube 미리보기 카드까지 확인된 경우에만 큐 항목을 published로 바꾸고 published_url을 기록한다. CRM sent는 성공 경로가 공급자 검증 직후 만든 1건만 인정하며 별도로 중복 기록하지 않는다.
